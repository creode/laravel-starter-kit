**Laravel Starter Kit** is an ultra-strict, type-safe [Laravel](https://laravel.com) skeleton engineered for developers who refuse to compromise on code quality. This opinionated starter kit enforces rigorous development standards through meticulous tooling configuration and architectural decisions that prioritize type safety, immutability, and fail-fast principles.

## Why This Starter Kit?

Modern PHP has evolved into a mature, type-safe language, yet many Laravel projects still operate with loose conventions and optional typing. This starter kit changes that paradigm by enforcing:

- **100% Type Coverage**: Every method, property, and parameter is explicitly typed
- **Zero Tolerance for Code Smells**: Rector and PHPStan at maximum strictness catch issues before they become bugs
- **Immutable-First Architecture**: Data structures favor immutability to prevent unexpected mutations
- **Fail-Fast Philosophy**: Errors are caught at compile-time, not runtime
- **Automated Code Quality**: Pre-configured tools ensure consistent, pristine code across your entire team
- **Node/npm**: Frontend tooling via DDEV (`ddev npm`)
- **Just Better Laravel Defaults**: Thanks to **[Essentials](https://github.com/nunomaduro/essentials)** / strict models, auto eager loading, immutable dates, and more...

This isn't just another Laravel boilerplate—it's a statement that PHP applications can and should be built with the same rigor as strongly-typed languages like Rust or TypeScript.

## Getting Started

> **Requires [DDEV](https://ddev.com) v1.25.5 or later** (it runs PHP 8.4, the database and Node). Run every PHP, Composer, Artisan and npm command through `ddev`, never on the host.

Use this repository as a template, clone your new repository, then:

```bash
ddev start

# Install dependencies, create .env, generate the app key, migrate and build assets
ddev composer setup

# Start the queue worker, log monitor and Vite dev server alongside the site
ddev composer dev
```

The site is served at `https://<project-name>.ddev.site`.

### Verify Installation

```bash
ddev composer test
```

Xdebug runs in coverage mode (set in `.ddev/config.yaml`), so Pest has a coverage driver and `ddev` commands stay quiet. To step debug, run a command with `XDEBUG_MODE=debug`.

> `composer test:type-coverage` currently fails inside Pest's type-coverage plugin with PHPStan 2.3 (`AnalyserResult::getCollectedData()` is undefined). This is an upstream incompatibility, not a problem with your project.

### Keeping AI guidance up to date

Guidelines and skills for AI agents are generated by [Laravel Boost](https://laravel.com/docs/boost). Update them with:

```bash
ddev artisan boost:update
```

`CLAUDE.md`, `AGENTS.md`, `GEMINI.md` and every `skills/` folder are **generated output; do not edit them by hand**. Put custom guidance in `.ai/guidelines/*.md` and custom skills in `.ai/skills/<name>/SKILL.md`, and Boost carries them into every agent on each update. Third-party packages (for example `internachi/modular`) are included through the `packages` list in `boost.json`.

## Available Tooling

### Development
- `composer dev` - Starts Laravel server, queue worker, log monitoring, and Vite+ dev server concurrently

### Code Quality
- `composer lint` - Runs Rector (refactoring), Pint (PHP formatting), and Oxfmt (JS/TS formatting)
- `composer test:lint` - Dry-run mode for CI/CD pipelines

### Testing
- `composer test:type-coverage` - Ensures 100% type coverage with Pest
- `composer test:types` - Runs PHPStan at level 9 (maximum strictness)
- `composer test:unit` - Runs Pest tests with 100% code coverage requirement
- `composer test` - Runs the complete test suite (type coverage, unit tests, linting, static analysis)

### Maintenance
- `composer update:requirements` - Updates all PHP and npm dependencies to latest versions
